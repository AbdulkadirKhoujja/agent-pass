Open source · experimental · offline-first proof of concept

AI agents should know what they're allowed to do.

AgentPass is exploring a clearer path from discovery and delegated permissions to independently checked actions and receipts. We start with a tiny public simulator that is honest about what it can and cannot prove.

Explore the open-source code Run the local demo
Important: this is not live agent identity infrastructure. The current implementation is a local, synthetic simulator. Its `agent_id` is unverified, its consent flag is not actual consent, its actions are fictitious, and its receipts are unsigned checksums. No AuthZEN, MCP or A2A compliance is claimed.

Seven steps toward a trustworthy action

01 / Discover

Find capabilities

Understand the service and the actions it declares.

02 / Understand

Read the boundaries

Check resources, terms and restrictions before doing anything.

03 / Request

Obtain authority

Future: authenticate the right actors and capture explicit scoped consent.

04 / Authorize

Enforce policy

Start from deny-by-default decisions, not inferred intentions.

05 / Execute

Perform one action

Currently, only a synthetic catalogue-read operation.

06–07 / Verify & receipt

Show what happened

Future: independently verifiable, privacy-preserving records.

Try it without accounts, tokens or infrastructure.

Python 3.10+. No third-party packages or network requests are needed.

git clone https://github.com/AbdulkadirKhoujja/agent-pass.git
cd agent-pass
python -m agentpass
python -m agentpass examples/denied_request.json
python -m unittest discover -s tests -v

Watch an allowed synthetic request generate an example result, then watch an unsupported action be denied. Inspect the source and submit an issue if the behaviour is unclear.

Frequently asked questions

Can AgentPass authenticate a real AI agent today?

No. The current demo does not prove identity or delegated consent.

Can I register this as an MCP server or A2A agent?

Not yet. There are no implemented compatible server endpoints or published Agent Cards. We will provide accurate discovery metadata after the integrations exist and pass tests.

Are the receipts cryptographically verifiable?

Not as authentication evidence. Current receipts contain an unsigned SHA-256 consistency checksum that any actor can recompute.
